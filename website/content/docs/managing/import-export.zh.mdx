## 支持的格式

Polymerium 支持四种用于导入和导出的整合包格式：

| 格式 | 扩展名 | 说明 |
|--------|-----------|-------|
| **Trident**（原生） | `.zip` | 保留包元数据、规则、选定的覆盖项、附件及导入层原生 Patch |
| **CurseForge** | `.zip` | 行业标准；兼容 CurseForge 应用、Prism 等 |
| **Modrinth** | `.mrpack` | 现代格式；兼容 Modrinth 应用、Prism 等 |
| **MultiMC** | `.zip` | 兼容 MultiMC、Prism Launcher 及其衍生版本 |

## 导入整合包

1. 点击 **+** 按钮创建新实例。
2. 选择**从文件导入**。
3. 选择整合包存档。
4. Polymerium 自动检测格式并导入：

   - 元数据被解析并写入实例的 `profile.json`。
   - 整合包文件（配置、资源）被提取到 `import/`。
   - 在线包引用在部署时解析；离线整合包中的文件从归档中读取。

5. 部署并游玩。

> **更新整合包？**如果实例是通过导入创建的，您可以重新导入同一整合包的较新版本。Polymerium 会用新文件替换 `import/`，同时保持 `persist/` 不变 — 您移动到那里的文件将被保留。

## 导出实例

1. 选择一个实例。
2. 打开实例菜单，选择**导出**。
3. 选择 **Trident** 或外部格式，检查该格式的选项及整合包元数据。
4. 按格式检查来源关联、离线模式和排除标签等选项，再保存整合包归档。整合包源文件始终随导出打包。

### 导出内容

| 内容 | 导出行为 |
|------|----------|
| 包引用和版本 | 在线 Trident 导出保留引用；离线 Trident 导出改为打包已解析的文件 |
| 整合包源（`import/`） | 存在时随归档打包，不受“包含来源信息”选项影响 |
| 实例图标和发行附件 | 存在且格式支持时包含 |
| 名称、作者、版本 | 可填写的字段因格式而异 |
| 原生 Patch | 仅 Trident 格式携带导入层；用户层留在本机 |
| 本地保留（`persist/`）及运行目录中非受管文件 | 均不导出；存档等个人数据需另行备份 |

### 格式特定说明

- **Trident Portable Instance（TPI）** 是 Polymerium 自有的整合包格式。在线导出保留包分组、标签、部署规则、选定的实例覆盖项、导入层原生 Patch 和附件，但不会打包整个实例。
- **CurseForge / Modrinth** 格式广泛兼容但会丢失 Polymerium 特定功能，如标签和规则。
- **MultiMC 格式**是最基础的 — 仅模组列表和配置。以文件夹形式导入的实例会保留本地组件定义，它们会变成[原生 Patch](/docs/advanced/patches)——GTNH、Cleanroom 这类实例的启动计划就是这样保住的。

## 在线与离线格式

并非所有整合包格式在底层的工作方式都相同：

- **CurseForge 和 Modrinth** 格式是**在线**格式 — 它们包含托管在这些平台上的模组的引用（包 URL），而不是实际的模组文件。导入时，启动器会解析这些引用并下载模组。

  这意味着 CurseForge 整合包理想情况下应仅引用 CurseForge 模组，Modrinth 整合包应仅引用 Modrinth 模组。如果您混合来源，整合包在发布时将无法通过平台审核。

- **MultiMC** 导出会打包文件供离线使用。部署时仍需要适合的 Minecraft 版本和加载器。

- **TPI** 既非纯在线也非纯离线。默认使用在线引用（Pref）并在部署时解析模组，但可选择离线模式将模组文件打包。详见下方 [Trident 便携实例](#trident-便携实例) 章节。

在为发布您的整合包选择格式时请记住这一点。

## Trident 便携实例

Trident Portable Instance（TPI）是 Polymerium 自有的整合包格式。在线导出相比外部格式保留更多实例配置中的包与部署元数据，并携带整合包源文件。它不是快照，也不是完整实例备份：本地保留（`persist/`）、运行目录（`build/`）、用户层 Patch 和账号凭据都不会随包转移。

### 包含内容

TPI `.zip` 归档始终包含索引和选项文件，其他内容则在存在时打包：

| 文件 | 用途 |
|------|---------|
| `trident.index.json` | 导出的实例配置数据：在线模式中的包、标签、规则、选定的覆盖项及来源分组 |
| `trident.options.json` | 导出选项（在线/离线模式、排除标签、来源关联及选定的覆盖项） |
| `icon.png`（或其他格式） | 实例图标——存在时自动打包 |
| `README.md` | 实例说明文档 |
| `CHANGELOG.md` | 实例更新日志 |
| `LICENSE` | 存在 `LICENSE.txt` 时从中读取的实例许可证 |
| `import/` | 存在时打包的整合包源文件 |
| `patches/data.patch.json` + `patches/import/` | 导入层 Patch：原生部署声明及其资产，连同启用状态与顺序一起打包 |

### 丰富的元数据

在线模式的 TPI 可以保留外部格式难以表示的声明：

- **每个模组的启用/禁用状态**——不仅知道有哪些模组，还知道哪些处于激活状态
- **标签**——用户自定义的分类标签
- **部署规则**——按模组的覆盖设置（目标路径、跳过、标准化）
- **实例覆盖**——JVM 参数、窗口大小、服务器地址、部署策略
- **来源追踪**——每个模组的来源信息，在导出/导入中完整保留
- **原生 Patch**——导入层的 Patch 连同资产、禁用条目与顺序一起传递；用户 Patch 留在本机，不随包传递

TPI 保存这些整合包声明，不保存完整的本机实例和个人数据。

### 默认在线，按需离线

TPI 是一种**混合**格式：

- **在线模式（默认）**：包保留为 Pref 引用，例如 `pref://modrinth/aC3cM3Vq@9I21YYxf`，部署时解析并下载文件。“包含来源信息”只控制原在线整合包的关联是否保留，不会移除整合包源文件。
- **离线模式（可选）**：将已启用包的解析结果打包进归档，并从导出的实例配置中移除这些包引用。它并不会备份本地保留或运行目录的所有文件。

在线模式使归档更小，由部署负责下载包。无论哪种模式，`trident.index.json` 都是可读的元数据文件。

### 实例附属文件

TPI 可以包含实例附件：如果实例主目录中存在图标、`README.md`、`CHANGELOG.md` 或 `LICENSE.txt`，导出时会携带它们（许可证在归档中名为 `LICENSE`）。这些文件描述的是实例本身，与整合包源文件分开。

### 理想的实例模板

TPI 可以作为整合包模板：导入其中的实例配置声明和已包含的整合包源文件来创建另一实例。开始游戏前，仍需分别检查 Java 运行时、账号及本地数据。

## 配方：纯引用清单

除了上面的整合包格式，Polymerium 还有一种轻量的纯引用格式：**配方**。配方是一份带名字的包引用清单，条目可带标签和备注——不含文件、不含配置，也不含 Minecraft 版本或加载器。用它分享一份精选的模组清单，并在配置实例时套用。参见 [配方 →](/docs/managing/recipes)。
