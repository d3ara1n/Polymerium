## Supported Formats

Polymerium supports four modpack formats for both import and export:

| Format | Extension | Notes |
|--------|-----------|-------|
| **Trident** (native) | `.zip` | Preserves package metadata, rules, selected overrides, attachments, and imported native patches |
| **CurseForge** | `.zip` | Industry standard; compatible with CurseForge app, Prism, etc. |
| **Modrinth** | `.mrpack` | Modern format; compatible with Modrinth app, Prism, etc. |
| **MultiMC** | `.zip` | Compatible with MultiMC, Prism Launcher, and derivatives |

## Importing a Modpack

1. Click the **+** button to create a new instance.
2. Choose **Import from file**.
3. Select the modpack archive.
4. Polymerium auto-detects the format and imports:

   - The metadata is parsed and written to your instance's `profile.json`.
   - Pack files (configs, resources) are extracted to `import/`.
   - Online package references are resolved when the instance is deployed; offline pack files are read from the archive.

5. Deploy and play.

> **Updating a modpack?** If the instance was created from an import, you can re-import a newer version of the same pack. Polymerium replaces `import/` with the new files while leaving `persist/` untouched — files you've moved there are preserved.

## Exporting an Instance

1. Select an instance.
2. Open the instance menu and choose **Export**.
3. Choose **Trident** or an external format, then review the format-specific options and pack metadata.
4. Review source association, offline mode, and excluded tags where available, then save the modpack archive. Pack Source files are included in the export.

### What Gets Exported

| Content | Export behavior |
|---------|-----------------|
| Package references and versions | Online Trident export retains references; offline Trident export bundles resolved files instead |
| Pack Source (`import/`) | Included in the archive when files exist, independently of the source information option |
| Instance icon and release attachments | Included when present and supported by the format |
| Name, author, version | Selected fields vary by format |
| Native patches | Only the import layer travels in Trident format; user patches stay local |
| Local Data (`persist/`) and unmanaged Run Directory files | Never exported; back up saves and other personal data separately |

### Format-Specific Notes

- **Trident Portable Instance (TPI)** is Polymerium's native modpack format. Online exports retain package grouping, tags, deployment rules, selected instance overrides, imported native patches, and attachments. It does not carry the whole instance.
- **CurseForge / Modrinth** formats are widely compatible but lose Polymerium-specific features like tags and rules.
- **MultiMC format** is the most basic — just the mod list and configs. Instances imported as folders keep their local component definitions: those become [native patches](/docs/advanced/patches), which is how GTNH and Cleanroom instances keep a working launch plan.

## Online vs. Offline Formats

Not all modpack formats work the same way under the hood:

- **CurseForge and Modrinth** formats are **online** — they contain references (package URLs) to mods hosted on those platforms, not the actual mod files. When you import one, the launcher resolves those references and downloads the mods.

  This means a CurseForge modpack should ideally only reference CurseForge mods, and a Modrinth modpack should only reference Modrinth mods. If you mix sources, the modpack won't pass platform review when publishing.

- **MultiMC** exports bundle files for offline use. Files supplied by a pack still need a suitable Minecraft version and loader when the instance is deployed.

- **TPI** is neither purely online nor offline. By default it stores online references (Prefs) and resolves mods at deploy time, but can optionally bundle mod files in offline mode. See the [Trident Portable Instance](#trident-portable-instance) section below for details.

Keep this in mind when choosing a format for publishing your modpack.

## Trident Portable Instance

Trident Portable Instance (TPI) is Polymerium's own modpack format. Online exports retain more of the profile's package and deployment metadata than external formats, alongside the Pack Source files. It is not a snapshot or a full backup of the instance: Local Data (`persist/`), the Run Directory (`build/`), user patches, and account credentials do not travel with the pack.

### What's Inside

A TPI `.zip` archive contains the index and options files, plus optional content when present:

| File | Purpose |
|------|---------|
| `trident.index.json` | Exported profile data: packages in online mode, tags, rules, selected overrides, and source grouping |
| `trident.options.json` | Export options (online/offline mode, excluded tags, source association, selected overrides) |
| `icon.png` (or other format) | Instance icon — bundled automatically if present |
| `README.md` | Instance readme |
| `CHANGELOG.md` | Instance changelog |
| `LICENSE` | Instance license, taken from `LICENSE.txt` when present |
| `import/` | Pack Source files, included when present |
| `patches/data.patch.json` + `patches/import/` | Import patch layer: native deployment declarations and their assets, packaged with their enabled state and order |

### Rich Metadata

In online mode, TPI preserves declarations that external formats cannot represent:

- **Per-mod enable/disable state** — not just which mods are included, but which are active
- **Tags** — user-defined labels for categorization
- **Deployment rules** — per-mod overrides for destination path, skipping, or normalization
- **Instance overrides** — JVM arguments, window size, server address, deploy strategy
- **Source tracking** — where each mod came from, preserved across export/import cycles
- **Native patches** — the imported patch layer travels with its assets, disabled entries and order; user patches stay local and never travel

TPI preserves these modpack declarations, not the complete local instance or its personal data.

### Online by Default, Offline When Needed

TPI is a **hybrid** format:

- **Online mode (default)**: Packages remain Pref references (for example, `pref://modrinth/aC3cM3Vq@9I21YYxf`). Deployment resolves and downloads their files. The source information option controls whether the original online modpack association travels; it does not remove Pack Source files.
- **Offline mode (optional)**: Bundles the enabled packages' resolved files into the archive and removes their package references from the exported profile. It is not a backup of Local Data or every file in the Run Directory.

Online mode keeps archives smaller and leaves package download to deployment. The `trident.index.json` remains human-readable in either mode.

### Instance Attachments

TPI can include instance-level attachments. If present in the instance home, the icon, `README.md`, `CHANGELOG.md`, and `LICENSE.txt` are exported (the license appears as `LICENSE` in the archive). These describe the instance itself rather than the game and remain separate from Pack Source files.

### Ideal as Instance Templates

You can use TPI as a modpack template: import its profile declarations and included Pack Source files to create another instance. Check its Java runtime, account, and any local data separately before playing.

## Recipes: Reference-Only Lists

Alongside the modpack formats above, Polymerium has a lightweight, reference-only format: **recipes**. A recipe is a named list of package references with optional tags and notes — no files, no configuration, and no Minecraft version or loader. Use it to share a curated mod selection and apply it when setting up an instance. See [Recipes →](/docs/managing/recipes).
