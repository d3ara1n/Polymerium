## 什么是配方？

配方（Recipe）是一份由用户维护的**包引用清单**——模组、资源包、光影包、数据包或存档——以一个名字保存，每个条目还可以带标签和备注。你可以把它理解为愿望单或预设包清单：一组命名好的包，可以应用到实例，也可以导出成文件分享。

配方只保存**引用**（`pref://` URI）。它不包含模组文件、不含配置，也不含 Minecraft 版本或加载器——这正是它与整合包的本质区别。

配方应用到实例后会形成**配方组**，与整合包组和集合使用同一套[包分组机制](/docs/managing/package-groups)，共同遵循优先级与重复包的处理规则。配方库中的清单与实例中的包组是两个对象：编辑配方不会自动同步已经应用到实例中的组。

## 配方与整合包

| | 配方 | 整合包 |
|--|------|--------|
| 内容 | 包引用 + 标签/备注 | Minecraft 版本、加载器、包、配置文件 |
| 作用对象 | 正在配置的实例——把包加进去 | 创建或更新整个实例 |
| 文件 | 轻量 JSON | `.zip` / `.mrpack` 归档 |

套用配方不会改变实例的 Minecraft 版本或模组加载器。配方中的项目引用会在套用时解析可用的包版本。与就地分组的[集合](/docs/managing/collections)不同，配方不依附于某个实例。

## 创建配方

1. 从应用菜单或工具栏按钮打开 **配方**。
2. 点击 **新建配方**，为配方命名并填写可选描述。
3. 打开配方，开始添加包。

## 添加包

1. 打开配方，点击 **添加**——这会打开包浏览器。
2. 浏览 CurseForge 和 Modrinth，把项目加入配方。
3. 每个条目都可以带**标签**（用于归类）和**备注**（记录值得留存的任何信息）。
4. 使用搜索框和资源类型筛选来浏览较大的配方。

在其他地方浏览时，已加入配方的项目会带有 **In Recipe**（在配方中）标记。

## 将配方应用到实例

打开已有实例的**配置**页。展开**获取更多**按钮的菜单，选择**导入配方**，然后挑选一个配方。Polymerium 会通过资源仓库解析每条引用，把条目加入对应配方组；无法解析的引用会以禁用状态加入，供你检查。点击组头可以展开或折叠，在组头菜单选择**查看详情**才会打开配方。

已经存在于其他组中的项目也可以出现在配方组中。两份条目都会保留在实例配置中，由[分组优先级](/docs/managing/package-groups)决定部署哪一份。应用配方后应检查顺序，尤其是它与其他配方或集合包含相同项目时。

从现有集合创建配方，或将已应用的配方组保留为本地集合，见[与配方互相转换](/docs/managing/collections#与配方互相转换)。Trident 整合包导出会将本机配方组转换为集合，因为本机配方库不会随整合包传递。

## 分享配方

- **导出**——在 **配方** 列表或配方详情页把配方导出为 JSON 文件。
- **导入**——在 **配方** 页面从 JSON 文件导入。
- 文件中每个条目以包引用形式存储，并携带其标签和备注。

## 删除配方

仍被实例引用的配方无法删除。Polymerium 会列出这些实例。在各实例的配置页中，**降级为集合**可以保留分组并解除配方关联；**解散组**会使成员变成散装包，**移除组**会从实例配置中删除这些条目。没有实例再引用配方后，就可以在配方库中删除它。

## 配方与版本控制

配方文件是带版本号的 JSON 文档，在版本控制中 diff 很干净——把配方文件放进 git 仓库与团队共享时很实用。参见 [Git 协作 →](/docs/guides/git-collaboration)。
