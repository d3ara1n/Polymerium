## 自动迁移（推荐）

Polymerium 可以直接从其他启动器的数据目录导入实例，无需先导出。支持的启动器：

- **MultiMC** 和 **Prism Launcher**
- **CurseForge 应用**
- **ATLauncher**
- **Modrinth 应用**

### 第 1 步：打开迁移向导

- 在 **设置** 中找到 **从启动器迁移**。
- 或在 **实例** 页面点击 **从其他启动器迁移**。

### 第 2 步：选择启动器及其数据目录

选择你要迁移的启动器。数据目录会预填为该启动器的默认位置——如果你使用了自定义目录，请手动修改。

### 第 3 步：扫描并选择实例

点击 **扫描**。Polymerium 会列出找到的每个实例，包含名称、Minecraft 版本和加载器。无法读取的实例会标注原因，你可以逐个勾选或跳过。

### 第 4 步：迁移

点击 **迁移**。对于每个选中的实例，Polymerium 会：

1. **识别模组** —— 对 mod、资源包和光影包目录中的 `.jar` 文件与 CurseForge 和 Modrinth 进行比对。识别成功的文件变为受追踪的包引用（缓存中已有则无需重新下载）；其余文件原样复制。
2. **复制其余所有文件** —— 配置文件、存档、截图、选项等被原样复制到新实例的**运行目录（`build/`）**。
3. **注册实例** —— 只有文件传输全部完成后才会创建配置（Minecraft 版本、加载器、包列表），因此失败的实例不会留下半成品配置。损坏的实例会被报告，迁移会继续处理其余实例。

你原来的启动器及其实例不受任何影响。接下来参见 [迁移之后](#迁移之后)。

## 向导会迁移哪些数据

| 数据 | 会迁移？ | 备注 |
|------|:--------:|------|
| Minecraft 版本 | ✅ | 从实例元数据读取 |
| 模组加载器（Fabric / Forge 等） | ✅ | |
| 模组 | ✅ | 与 CurseForge / Modrinth 比对识别，变为受追踪的包 |
| 配置、存档、截图、选项 | ✅ | 原样复制到运行目录（`build/`） |
| 账号凭据 | ❌ | 使用同一个账号重新登录——存档数据与玩家 UUID 绑定 |
| JVM 设置 | ❌ | 使用实例默认值；如有需要在设置中重新配置 |

## 账号与存档数据

存档与**玩家 UUID** 绑定，而不是与用户名或你在启动器中看到的账号绑定。换账号登录不会丢失存档文件——存档仍然能加载，但你会以**新玩家的身份**进入：绑定在旧 UUID 上的物品栏、出生点和进度都不会跟随你。

| 你之前用的是 | 你现在登录的是 | 结果 |
|--------------|---------------|------|
| 微软账号 | **同一个微软账号** | ✅ UUID 一致——存档与离开时完全一致 |
| 离线模式（用户名） | **同一个离线用户名** | ✅ UUID 由用户名推导——存档匹配 |
| 离线模式 | **不同的离线用户名** | ❌ UUID 不同——存档能加载，但你是新玩家 |
| 离线模式 | 微软账号（或反之） | ❌ UUID 不同——同样的问题 |
| 第三方外置登录（authlib-injector，如 LittleSkin） | **同一个外置登录服务器和账号** | ✅ UUID 一致 |
| 第三方外置登录 | 其他服务器，或不再使用外置登录 | ❌ UUID 不同——存档中的玩家数据不会关联 |

存档文件永远不会被删除——数据只是留在旧的 UUID 名下。要保留进度，请使用迁移前同一个账号登录。第三方外置登录请参见 [设置 Authlib Injector（外置登录）→](/docs/guides/setup-authlib)。

## 启动器的目录结构

如果你的启动器没有适配器，就需要手动迁移——第一步是找到它的数据位置。启动器分为两类：

| 类型 | 实例的存储方式 | 示例 |
|------|---------------|------|
| **扁平式** | 一个游戏文件夹存放所有内容，所有安装共用它 | 官方 Minecraft 启动器（`<data>/.minecraft/`） |
| **每实例一文件夹** | 每个实例都有自己的文件夹，内部带有独立的 `.minecraft` 等价目录 | MultiMC 系（`<data>/instances/<名称>/`）、CurseForge 应用、ATLauncher、Modrinth 应用 |

对于「每实例一文件夹」的启动器，实例的游戏数据就是包含 `mods/`、`saves/` 和 `options.txt` 的那个文件夹；对于扁平式启动器，则是那个唯一的 `.minecraft` 文件夹。一旦确认哪个文件夹是一个实例的游戏数据，下面的手动流程就适用于任何启动器。

## 手动迁移（任意启动器）

当没有适配器时——典型如官方启动器——手动迁移虽然麻烦，但思路清晰：

### 第 1 步：创建匹配的实例

1. 点击 Polymerium 中的 **+** 按钮。
2. 选择 **新建实例**，并选择与你之前游玩**相同的 Minecraft 版本**。
3. 如果你使用了模组，选择**相同的模组加载器**（Fabric、Forge、NeoForge 或 Quilt）及兼容版本。

> **不确定用了哪个加载器或版本？** 在「每实例一文件夹」的启动器中，查看实例的元数据文件。在官方启动器中，打开 `.minecraft/versions/`——如果看到类似 `1.21.4-fabric-0.16.9` 的文件夹，说明是 Fabric 0.16.9（Minecraft 1.21.4）；如果都是纯版本号文件夹（如 `1.21.4`），说明是原版（无加载器）。

### 第 2 步：复制游戏数据

你的模组、存档、配置、截图和设置都在一起——就在启动器的游戏数据文件夹中（见上文 [启动器的目录结构](#启动器的目录结构)）。这个文件夹就是 Minecraft 视作游戏主目录的地方，而实例的**运行目录（`build/`）**同样如此。把文件夹的内容按原结构复制进 `build/`，所有东西就会像在原来的启动器里一样加载。

1. 打开启动器的游戏数据文件夹。
2. 将 `mods/`、`resourcepacks/`、`shaderpacks/`、`saves/`、`screenshots/`、`options.txt` 和 `servers.dat`——所有游戏生成的或你添加的文件——复制到 `build/`，保持目录结构一致。
3. 跳过 `versions/`、`assets/`、`libraries/`——Minecraft 本体、资产和库由 Polymerium 的共享缓存提供，复制它们只会造成重复。

**可选——作为包追踪。** 复制进 `build/` 的文件不会被追踪，因此无法作为包更新。如果你想跟踪其中一部分，且它们在 CurseForge 或 Modrinth 上存在，可以改成包引用的形式：

- **从文件导入资源** —— 在实例页面把 `.jar` 拖进来，Polymerium 识别后作为包引用添加。
- **添加包** —— 在对话框中搜索 CurseForge 或 Modrinth 并手动添加。

两种方式都只能一次处理一个文件，模组很多时不划算——直接按上面的方式复制文件更快，需要跟踪的再单独转换。

文件就位后，参见 [迁移之后](#迁移之后) 来部署、登录并保护你的数据。

### 常见问题

- **存档不见了：** 确认你把 `saves/` 复制进了 `build/`，并且复制后执行了部署。
- **设置没有带过来：** 检查 `options.txt` 是否在 `build/` 中。
- **模组没有加载：** 确认模组加载器版本匹配。Fabric 模组不能在 Forge 上加载，反之亦然。

## 迁移之后

无论你走的是自动还是手动——都用这几步收尾：

1. **添加游戏账号** —— 凭据不会迁移。打开 **账号** 并登录，请使用**迁移前同一个账号**——详见 [账号与存档数据](#账号与存档数据)。
2. **部署并开始游戏** —— 启动实例，Polymerium 会自动部署。
3. **保护你的数据** —— 迁移的文件落在**运行目录（`build/`）**中，而**重置会清空该目录**。请将你想保留的内容（存档、截图、配置）移入**本地保留（`persist/`）**，这样重置后依然存在。详见 [目录模型](/docs/concepts/directory-model)。

## 备选方案：导入导出的整合包

如果你的启动器支持导出整合包——Prism Launcher 和 MultiMC 可以导出 MultiMC、Modrinth 或 CurseForge 格式——你也可以直接导入归档文件：

1. 从其他启动器导出实例（MultiMC 格式在此场景下保真度最高）。
2. 在 Polymerium 中点击 **+** → **从文件导入**，选择归档文件。Polymerium 会自动检测格式、解析模组并创建实例。
导入完成后，参见 [迁移之后](#迁移之后)。

当你手里只有整合包归档文件（例如从网站下载的）而没有启动器安装时，这条路径同样适用。

## 注意事项

- **Polymerium 使用符号链接**——请确保在 Windows 上启用了开发者模式。
- **模组文件是共享的**——你不需要重新下载已经是 CurseForge/Modrinth 格式的模组；Polymerium 会从缓存中解析它们。
- **你之前的启动器实例不受影响**——迁移和导入都会创建新实例；不会删除或修改原启动器中的任何内容。
