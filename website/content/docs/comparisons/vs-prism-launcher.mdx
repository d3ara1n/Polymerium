## Overview

Polymerium and Prism Launcher are both open-source Minecraft launchers that support multiple instances, mod loaders and modpack platforms, and both can customize an instance's launch data through patch or component declarations. They differ mainly in how an instance is stored and rebuilt.

### Key Difference at a Glance

| Aspect | Polymerium | Prism Launcher |
|--------|:----------:|:--------------:|
| **Instance representation** | Metadata file (`profile.json`) + shared cache | Instance folder (`instance.cfg`, `mmc-pack.json`, `minecraft/`) |
| **Storage model** | Mod files are symlinked from one shared cache | Mod files are copied per instance, or linked when an instance is copied with links |
| **Architecture** | Compile-on-read (metadata → deploy) | File-based instance folders |
| **Launch customization** | Ordered patch documents in `patches/` | Component JSON on the Version page |
| **License** | MIT | GPL-3.0 |

## Feature Comparison

### Storage & Disk Usage

| Feature | Polymerium | Prism Launcher |
|---------|:----------:|:--------------:|
| **Shared game files (assets, libraries, Java)** | ✅ One shared cache | ✅ One shared cache |
| **Shared mod files** | ✅ Central cache, symlinked into every instance | ⚠️ Central Mods folder as a source, but files are copied into each instance |
| **Links and clones** | ✅ Symlinks; Windows requires Developer Mode | ✅ Hard links, symbolic links, recursive linking and copy-on-write clones, on Windows, macOS and Linux (filesystem permitting) |
| **Modpack version switching** | ✅ Metadata change and redeploy | ✅ Update in place from the Managed Pack page |

Both launchers share Minecraft's assets, libraries and Java runtimes, so the practical difference is mod files rather than game files. Polymerium links every mod from one cache. Prism Launcher stores a copy per instance unless you copy an instance with its link or clone options; files installed from its Central Mods folder are copied too.

---

### Instance Architecture

| Feature | Polymerium | Prism Launcher |
|---------|:----------:|:--------------:|
| **Instance definition** | Single `profile.json` file | `instance.cfg` + `mmc-pack.json` + `minecraft/` folder |
| **File organization** | Pack Source (`import/`) / Local Data (`persist/`) / Run Directory (`build/`) | One instance folder, plus shared `assets/`, `libraries/`, `meta/` and `java/` |
| **Reset/rebuild** | ✅ Clear the Run Directory and redeploy from metadata; Pack Source and Local Data survive | ⚠️ No whole-instance reset; mods and loader components can be reinstalled individually |
| **Modpack updates** | ✅ In-place; Pack Source is replaced, Local Data is preserved | ✅ In-place from the Managed Pack page; edits to configuration files are not protected from the update |
| **Copy an instance** | ⚠️ Export as a Trident pack and import it again | ✅ Copy with hard links, symbolic links or copy-on-write clones, optionally keeping play time |

**Polymerium's directory model:**

```
instances/my-pack/
├── import/    ← Pack Source
├── persist/   ← Local Data you explicitly preserve
└── build/     ← Run Directory Minecraft writes to
```

This separation means:
- Modpack updates don't overwrite data you've placed in Local Data (`persist/`)
- Resets can delete saves stored only in the Run Directory (`build/`), so worlds must be moved to `persist/saves/` before they are protected
- Reproducible game files in the Run Directory can be rebuilt from metadata and cache

Prism Launcher additionally installs LiteLoader and can filter its mod browser by several legacy loaders (Ornithe, LegacyFabric, Rift, Babric, BTA), although those cannot be installed from the launcher either. Polymerium supports the four main loaders as first-class choices and covers other runtimes through patch documents.

### GTNH & Cleanroom Support

| Feature | Polymerium | Prism Launcher |
|---------|:----------:|:--------------:|
| **GTNH instance** | ✅ Import the instance and launch | ✅ GTNH ships Prism ZIPs and recommends Prism Launcher |
| **Cleanroom** | ✅ Import the vendor's MultiMC instance | ✅ Import the vendor's MultiMC instance |
| **Component-format instance** | ✅ Local component definitions convert to native patches on import | ✅ Component definitions are consumed as they are |

GTNH and Cleanroom ship launch data that a Minecraft version and a mod loader cannot describe, and both are distributed for component-based launchers: GTNH publishes a Prism ZIP, and Cleanroom publishes a MultiMC instance. Prism Launcher is their intended target and consumes the component definitions directly. Polymerium is not the target, but it reads the same definitions and converts them into [native patches](/docs/advanced/patches), so these instances deploy and launch through the ordinary pipeline without per-modpack support code.

### Mod Management

| Feature | Polymerium | Prism Launcher |
|---------|:----------:|:--------------:|
| **CurseForge integration** | ✅ Built-in | ✅ Built-in |
| **Modrinth integration** | ✅ Built-in | ✅ Built-in |
| **Mod tags** | ✅ Tags with multi-tag filtering | ❌ No mod tags; instances can be grouped |
| **Deployment rules engine** | ✅ Per-package selector with skip, redirect and rename actions | ❌ Per-mod enable/disable and pack-level `overrides/` only |
| **Batch operations** | ✅ Bulk update with tag-based exclusion | ✅ Bulk update for all or selected mods |
| **Enable/disable mods** | ✅ | ✅ |

A deployment rule in `profile.json` (`setup.rules`) looks like this:

```json
{
  "selector": {
    "type": "and",
    "children": [
      { "type": "repository", "repository": "curseforge" },
      { "type": "kind", "kind": "dataPack" }
    ]
  },
  "destination": "datapacks/"
}
```

`destination` is a folder, and the file name is kept. Rules can also be edited from the instance's Setup page.

## When to Choose Each

### Choose Polymerium if you:

- ✅ Want one mod file shared by every instance instead of a copy per instance
- ✅ Frequently switch between mod loaders or modpack versions
- ✅ Develop or maintain modpacks (Git-friendly workflow)
- ✅ Want to experiment safely (snapshots)
- ✅ Need third-party auth (Authlib Injector) or an offline or trial account
- ✅ Prefer Chinese localization
- ✅ Want AI agent automation (MCP mode)
- ✅ Need per-package deployment control (rules engine)

### Choose Prism Launcher if you:

- ✅ Prefer a plain instance folder you can edit, copy and back up by hand
- ✅ Need GPL-3.0 licensing for your project
- ✅ Install legacy loaders such as LiteLoader
- ✅ Want link-based or copy-on-write instance copies
- ✅ Want file-based custom themes, icon themes and cat packs
- ✅ Want the launcher GTNH and Cleanroom are actually packaged for
- ✅ Want a mature, battle-tested launcher with a large translation community

## Where Polymerium Differs

### MCP Mode & AI Integration

Polymerium ships a built-in MCP server. Run `trident --mcp` and an AI agent can create instances, add packages, take snapshots, deploy and launch — 30+ tools covering the workflow. Prism Launcher has no MCP integration.

### Snapshots & Diff

Save managed instance state before making changes, then restore or compare later. Great for:

- Testing mod updates
- Experimenting with configurations
- Debugging crashes
- Rolling back broken setups

### Git-Friendly Modpack Development

Your instance source is clean: `profile.json` + `import/` + icon + README + CHANGELOG. Add a `.gitignore` to exclude `build/` and `persist/`, and you have a version-controlled modpack ready for collaboration.

## Summary

Polymerium and Prism Launcher both manage Minecraft instances, loaders and modpacks, and both can customize an instance's launch data instead of shipping a fixed pipeline. The practical differences are where that data lives and how instances are stored.

- **Polymerium** keeps an instance as metadata plus a shared cache: mod files are linked rather than copied, Local Data is protected across updates, and instance state can be snapshotted and diffed. It also ships a CLI and an MCP server, and runs component-based instances such as GTNH and Cleanroom by converting their declarations into native patches.

- **Prism Launcher** keeps each instance as a self-contained folder. It is the launcher GTNH and Cleanroom are packaged for, installs LiteLoader, supports link-based and copy-on-write instance copies, and offers file-based custom themes and a large translation community.

Both are solid choices — pick the one whose instance model matches how you work.
