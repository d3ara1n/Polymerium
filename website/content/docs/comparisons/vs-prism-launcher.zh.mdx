## 概览

Polymerium 和 Prism Launcher 都是开源 Minecraft 启动器，支持多实例、多种模组加载器和整合包平台，也都能通过 Patch 或组件声明定制实例的启动数据。两者的主要区别在于实例如何存储与重建。

### 一眼看差异

| 方面 | Polymerium | Prism Launcher |
|--------|:----------:|:--------------:|
| **实例表示** | 元数据文件（`profile.json`）+ 共享缓存 | 实例文件夹（`instance.cfg`、`mmc-pack.json`、`minecraft/`） |
| **存储模型** | 模组文件从同一份共享缓存符号链接而来 | 每个实例复制一份；复制实例时选择链接才会链接 |
| **架构** | 编译时读取（元数据 → 部署） | 基于文件的实例文件夹 |
| **启动定制** | `patches/` 下有序的 Patch 文档 | 版本编辑器里的组件 JSON |
| **许可** | MIT | GPL-3.0 |

## 功能对比

### 存储与磁盘占用

| 功能 | Polymerium | Prism Launcher |
|------|:----------:|:--------------:|
| **共享游戏文件（资产、库、Java）** | ✅ 一份共享缓存 | ✅ 一份共享缓存 |
| **共享模组文件** | ✅ 中心缓存，符号链接到每个实例 | ⚠️ 有中心 Mods 文件夹作为来源，但文件仍是复制进各实例 |
| **链接与克隆** | ✅ 符号链接；Windows 需要开发者模式 | ✅ 硬链接、符号链接、递归链接与写时复制克隆，Windows / macOS / Linux 均可用（受文件系统限制） |
| **整合包版本切换** | ✅ 改元数据后重新部署 | ✅ 在「托管整合包」页面原地更新 |

两者都共享 Minecraft 的资产、库与 Java 运行时，所以实际差别在模组文件而非游戏文件：Polymerium 从一份缓存链接每个模组，Prism Launcher 默认每个实例存一份副本，只有在复制实例时选用链接或克隆才会共享；从它的中心 Mods 文件夹装入的文件同样是复制。

---

### 实例架构

| 功能 | Polymerium | Prism Launcher |
|------|:----------:|:--------------:|
| **实例定义** | 单个 `profile.json` 文件 | `instance.cfg` + `mmc-pack.json` + `minecraft/` 文件夹 |
| **文件组织** | 整合包源（`import/`）/ 本地保留（`persist/`）/ 运行目录（`build/`） | 一个实例文件夹，外加共享的 `assets/`、`libraries/`、`meta/` 与 `java/` |
| **重置/重建** | ✅ 清空运行目录后按元数据重新部署；整合包源与本地保留不受影响 | ⚠️ 没有整体重置；模组与加载器组件可以逐个重装 |
| **整合包更新** | ✅ 原地更新；替换整合包源，保留本地保留 | ✅ 在「托管整合包」页面原地更新；更新不会保护你改过的配置文件 |
| **复制实例** | ⚠️ 导出为 Trident 格式后重新导入 | ✅ 用硬链接、符号链接或写时复制克隆复制，可选择保留游玩时长 |

**Polymerium 的目录模型：**

```
instances/my-pack/
├── import/    ← 整合包源
├── persist/   ← 你显式保留的本地数据
└── build/     ← Minecraft 写入的运行目录
```

这层分离意味着：
- 整合包更新不会覆盖你放进本地保留（`persist/`）的数据
- 重置会删除只存在于运行目录（`build/`）的存档，所以世界要先移到 `persist/saves/` 才受保护
- 运行目录里可复现的游戏文件都能按元数据与缓存重建

### 模组加载器支持

| 功能 | Polymerium | Prism Launcher |
|------|:----------:|:--------------:|
| **Fabric** | ✅ | ✅ |
| **Forge** | ✅ | ✅ |
| **NeoForge** | ✅ | ✅ |
| **Quilt** | ✅ | ✅ |
| **LiteLoader** | ❌ | ✅ 可安装 |
| **Ornithe / LegacyFabric / Rift / Babric / BTA** | ❌ | ⚠️ 仅作为模组浏览过滤项，不能安装 |
| **自定义加载器版本** | ✅ 选择指定版本 | ✅ 在版本编辑器里选择版本 |
| **切换加载器** | ✅ 改加载器后重新部署 | ✅ 在版本编辑器里安装或替换组件 |

Prism Launcher 额外能安装 LiteLoader，模组浏览也支持按若干旧版加载器（Ornithe、LegacyFabric、Rift、Babric、BTA）过滤，但这些旧版加载器同样无法从启动器安装。Polymerium 把四种主流加载器作为一等选项，其余运行时通过 Patch 文档覆盖。

### GTNH 与 Cleanroom 支持

| 功能 | Polymerium | Prism Launcher |
|------|:----------:|:--------------:|
| **GTNH 实例** | ✅ 导入实例后即可启动 | ✅ GTNH 直接发布 Prism ZIP，并推荐使用 Prism Launcher |
| **Cleanroom** | ✅ 导入官方发布的 MultiMC 实例 | ✅ 导入官方发布的 MultiMC 实例 |
| **组件格式实例** | ✅ 导入时本地组件定义转为原生 Patch | ✅ 直接消费组件定义 |

GTNH 与 Cleanroom 自带版本号加加载器描述不了的启动数据，两者都是面向组件式启动器分发的：GTNH 发布 Prism ZIP，Cleanroom 发布 MultiMC 实例。Prism Launcher 是它们的目标平台，直接消费这些组件定义；Polymerium 不是目标平台，但会读取同一份定义并转换为[原生 Patch](/docs/advanced/patches)，因此这类实例同样走常规部署管线，不需要逐个整合包写支持代码。

### 模组管理

| 功能 | Polymerium | Prism Launcher |
|------|:----------:|:--------------:|
| **CurseForge 集成** | ✅ 内置 | ✅ 内置 |
| **Modrinth 集成** | ✅ 内置 | ✅ 内置 |
| **模组标签** | ✅ 标签与多标签过滤 | ❌ 没有模组标签；实例可以分组 |
| **部署规则引擎** | ✅ 按条件选择包并执行跳过、重定向、重命名 | ❌ 只有按模组启用/禁用与整合包级 `overrides/` |
| **批量操作** | ✅ 批量更新，支持按标签排除 | ✅ 对全部或选中模组批量更新 |
| **启用/禁用模组** | ✅ | ✅ |

`profile.json` 的 `setup.rules` 里的一条部署规则长这样：

```json
{
  "selector": {
    "type": "and",
    "children": [
      { "type": "repository", "repository": "curseforge" },
      { "type": "kind", "kind": "dataPack" }
    ]
  },
  "destination": "datapacks/"
}
```

`destination` 是目录，文件名保持不变。规则也可以在实例的 Setup 页面编辑。

## 如何选择

### 选择 Polymerium 如果你：

- ✅ 希望每个实例共享同一份模组文件，而不是各存一份副本
- ✅ 经常在模组加载器或整合包版本之间切换
- ✅ 开发或维护整合包（Git 友好的工作流）
- ✅ 想安全地实验（快照系统）
- ✅ 需要第三方验证（Authlib Injector）或离线、试用账号
- ✅ 偏好中文本地化
- ✅ 想要 AI Agent 自动化（MCP 模式）
- ✅ 需要按包精确控制文件部署（规则引擎）

### 选择 Prism Launcher 如果你：

- ✅ 偏好可以直接手工编辑、复制和备份的实例文件夹
- ✅ 需要为你的项目使用 GPL-3.0 许可
- ✅ 需要安装 LiteLoader 这类旧版加载器
- ✅ 想要基于链接或写时复制的实例副本
- ✅ 想要文件式自定义主题、图标主题与 cat pack
- ✅ 想要 GTNH 与 Cleanroom 实际打包针对的那个启动器
- ✅ 想要一个成熟、经过战斗测试且翻译社区庞大的启动器

## Polymerium 的不同之处

### MCP 模式与 AI 集成

Polymerium 内置 MCP 服务器：运行 `trident --mcp`，AI Agent 就能创建实例、添加包、拍快照、部署并启动——30+ 工具覆盖整个流程。Prism Launcher 没有 MCP 集成。

### 快照与对比

改动前先保存受管理的实例状态，之后可以恢复或对比。适合：

- 测试模组更新
- 试验各种配置
- 排查崩溃
- 回滚坏掉的配置

### Git 友好的整合包开发

你的实例源文件很干净：`profile.json` + `import/` + 图标 + README + CHANGELOG。加一个 `.gitignore` 排除 `build/` 与 `persist/`，就得到一个可以协作的、纳入版本控制的整合包。

## 总结

Polymerium 和 Prism Launcher 都能管理 Minecraft 实例、加载器与整合包，也都能定制实例的启动数据，而不是只提供固定的启动管线。实际差别在于这些数据放在哪里、实例如何存储。

- **Polymerium** 把实例保存为元数据加一份共享缓存：模组文件是链接而不是复制，本地保留在更新中受保护，实例状态可以拍快照与对比。它还内置 CLI 与 MCP 服务器，并通过把组件定义转换为原生 Patch 来运行 GTNH、Cleanroom 这类实例。

- **Prism Launcher** 把每个实例保存为自包含的文件夹。它是 GTNH 与 Cleanroom 实际打包针对的启动器，能安装 LiteLoader，支持基于链接与写时复制的实例复制，并提供文件式自定义主题与庞大的翻译社区。

两者都是可靠的选择——按你的实例模型偏好挑一个即可。
