## 验证环境

- 主开发平台 macOS（Apple Silicon）：执行全部流程；`win-x64`、`linux-x64`、`osx-arm64` 实际发布产物分别完成平台冒烟。
- 部署语义部分由 trident CLI 确定性驱动（Polymerium 与 CLI 共用同一 Core 部署引擎），CLI 由 `submodules/Trident.Net`（`main` 分支，`9dfd414`，含修复 `558ba29` 与文档纠正 `3e0661b`）发布，home 隔离于 `/tmp`；GUI 表现项、游戏内观察与 Workspace/快照人工执行。
- CLI 验证实例：Minecraft 1.21.1（vanilla）+ `pref://modrinth/uvpymuxq@w4ReEpuG`（Better Leaves 9.6 资源包）；缺陷复现实例克隆自真实失败实例（NeoForge 1.21.1 / neoforge 21.1.248 + 5 个 CurseForge 包）。
- Polymerium：主仓库 `fb919e74` + 子模块 `9dfd414` 构建的本地版本。
- 一次性 harness 与其日志位于 `/tmp/projection-validation/`（按约定不落仓库，随系统清理消失）。

## 方法偏差（经所有者批准）

原发版门槛要求存在 GUI 入口的操作一律从 GUI 发起。实际采用双轨：文件系统投影语义（仲裁、清单、迁移、形态转换、链接、重置）经 CLI 脚本在单一实例上增量验证（16 阶段 / 96 项断言全通过，含幂等全树指纹比对）；GUI 专属表现项（进度、首页状态分类、Workspace、快照、更新界面、警告文案）人工走查。中断重试（流程十四）按所有者决定标记不适用：软件不支持中断恢复语义，不承诺中断后行为。

## 发现的问题与处置

1. **OS 元数据文件阻断部署**（长期存在，非本次改造引入）：Finder/Explorer 在管理目录中落下的 `.DS_Store` 等再生元数据被收集为投影候选，persist 侧新增噪音文件与 build 侧同名无归属文件触发「无归属证据则冲突」，部署在规划阶段中止并提示重置，任何接管操作未执行。修复于子模块 `558ba29`（后续 `9dfd414` 将无清单时的回退归属枚举同样排除 OS 元数据）：封闭名单（`.DS_Store`、`Thumbs.db`、`desktop.ini`、`._*`）不投影、不迁移、接管清理时可删除，其余位置按未管理内容保留。克隆失败实例复验部署成功（世界完整迁移、噪音零进入 persist），harness 扩展该场景后 96/96 通过，真实实例重新部署人工确认通过。
2. **CLI 文档超前实现**：`docs/CLI.md` 等四份文档记载了未实现的 `--home` 全局选项，实际机制为 `TRIDENT_HOME` 环境变量及目录探测顺序。已纠正（子模块 `3e0661b`）。

## 最终结论

全部可执行流程通过，唯一不适用项（流程十四）有明确且经确认的原因，缺陷修复已复验。**允许发版。**
