# 拼音首字母搜索

## 背景

用户群以中文用户为主，实例名、集合名、标签等大量检索对象是用户自定义的中文名。当前搜索只能按原文子串匹配，中文输入成本高——想找"英灵殿"得切输入法打全名。拼音/首字母检索是中文工具产品的成熟做法。经讨论确认要做。

## 做什么

为中文文本提供"原文 / 全拼 / 拼音首字母"三种形态的匹配能力，接入实例搜索；命令面板（见 `GLOBAL-COMMAND-PALETTE.md`）落地后同为消费方。

## 期望效果

输入 `yld` 或 `yinglingdian` 均能命中"英灵殿"；纯英文/数字名称的现有匹配行为不变。

## 调研所得的注意事项

- 候选 NuGet 包全部老旧（2026-09 核实）：PinYinConverterCore 1.0.2（2017）、TinyPinyin.Net 1.0.2（2020，移植自主流 Java 库 TinyPinyin，多音字处理相对最好）、Pinyin4Net 1.0.0（2012，太老）。倾向 TinyPinyin.Net；这类包很小且自包含，引入前可整体审一遍。自行内嵌拼音字典属重复造轮子，不考虑。
- 汉字→拼音转换有成本，名称列表会被反复检索：转换结果必须缓存（按名称缓存一次转换形态），不能在每次按键的过滤管道里现算。
- 多音字（"重庆"、"银行"）取常用读音即可；首字母匹配场景容错高，不必追求全读音展开。
- 匹配逻辑应落在现有搜索的 DynamicData Filter 管道内，不为它单开订阅或改数据模型——模型保持纯数据，匹配是检索策略不是数据属性。
