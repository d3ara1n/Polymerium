# 工作区初始化

## 背景

Workspace 是整合包开发的主要工作入口，但一个新实例是否已经具备可用于开发的整合包源和版本控制基础，目前不够明确。用户可能只有普通实例、只有运行目录，或者已经准备了整合包源但尚未建立项目协作环境。

## 做什么

在 Workspace 中提供整合包开发项目的初始化入口，并识别实例当前是否已完成初始化。初始化应围绕整合包源、可被开发和发布的项目内容以及版本控制基础展开，同时明确 Git 未初始化、Pack Source（`import/`）未创建等状态分别代表什么。

## 期望效果

开发者打开 Workspace 就能知道当前实例能否进入整合包开发流程，以及还缺少哪些基础条件。完成初始化后，Workspace 应成为从运行中调整内容、审阅变更、同步到 Pack Source 并继续协作的明确入口，而不是只有在用户已经手动准备好目录后才有意义。

## 注意事项

“未初始化”可能包含不同状态，Git 仓库不存在与 Pack Source（`import/`）不存在不能未经区分地视为同一种问题。初始化判定和后续提示需要尊重实例是否来自外部整合包、是否仍受来源锁定，以及用户是否只想使用 Workspace 而暂不采用 Git。
