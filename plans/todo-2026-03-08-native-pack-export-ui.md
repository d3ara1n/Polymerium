# 原生与低级格式导出界面

## 背景

整合包导出目前只能在文件管理器中补齐更新日志等发布信息。Trident 格式能够承载更多项目元数据，但外来整合包格式通常只支持一组较小的兼容字段，不能为每种格式分别定制一套完整的项目发布模型。

## 做什么

重新设计导出 UI，区分面向 Trident 的原生格式导出与面向外来整合包格式的低级导出。原生格式提供适合项目开发和发布的完整元数据编辑入口；低级格式共享必要的兼容配置和格式选择，并明确哪些项目因目标格式能力不足而不可用。

## 期望效果

整合包作者可以在 Polymerium 中处理 Trident 项目的名称、作者、版本、更新日志、图标、截图、许可证、依赖和其他可表达的附加信息，而无需绕到文件管理器。切换到 Modrinth、CurseForge 或其他外来格式时，界面会收敛到这些格式真正支持的共同字段，不会制造“填写了但不会被导出”的假象。

## 注意事项

不能为了统一 UI 而把所有格式强行套进同一套元数据模型，也不应让低级格式出现目标格式无法承载的配置项。格式选择可以共享，但原生格式与低级格式的配置能力、提示和验证需要保持清晰边界。Trident 负责打包能力，发布到资源平台等属于外围 CD 工作流，不纳入本计划。
