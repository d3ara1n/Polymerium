# 启动计划导出与 Portable Instance 支持

## 背景

原生 LaunchPlan 出现后，实例可能包含影响启动行为的持久计划层。现有部分导出格式只能表达 Profile、包和文件，无法完整承载启动计划；如果继续静默导出，会造成导出实例与源实例的启动行为不一致。

Trident Portable Instance 作为原生实例格式，需要能够完整携带实例的启动计划，并与 Profile、Pack Source、Local Data 和 Run Directory 保持一致的生命周期边界。

## 目标

- 让不支持 LaunchPlan 的导出格式在导出时明确报告限制，而不是静默丢弃启动意图。
- 为 Trident Portable Instance 定义并实现原生 LaunchPlan 的携带、导入、导出和恢复语义。
- 保证 Portable Instance 在不同机器间移动后仍能恢复可执行的启动计划和其受管理的本地引用。
- 使导出诊断能够区分完整导出、部分导出和因启动计划无法表达而失败的情况。

## 预期效果

- 用户不会得到一个表面导出成功但启动行为已经改变的实例包。
- 支持原生 LaunchPlan 的格式可以完整恢复 Profile 与启动计划层。
- 不支持启动计划的格式会在导出界面或命令输出中给出可操作的提示。
- Portable Instance 的启动计划、实例文件和部署快照边界清晰，避免把缓存结果误当成持久配置。

## 已知约束

- 导出诊断属于导出结果，不写入 LaunchPlan 文件模型。
- Portable Instance 应携带规范化原生计划，不依赖外部来源格式。
- 不支持的外部格式不能通过静默丢弃字段伪装成完整导出。
- 本阶段不预设具体 UI；先定义核心导出契约和格式语义，再由宿主接入展示。
