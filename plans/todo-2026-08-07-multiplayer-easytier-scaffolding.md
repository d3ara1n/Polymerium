# Polymerium 内置 Minecraft 联机（EasyTier + Scaffolding）

> 制定日期：2026-XX-XX
> 定位：启动器核心能力之一，面向大众玩家的一键联机。
> 当前状态：构想（调研完成，未实施）。
> 依赖：无。

---

## 做什么

在 Polymerium 内集成 Minecraft Java 版联机能力：玩家无需公网 IP、无需端口映射、无需理解防火墙，即可像局域网联机一样开房间/加房间，且与 HMCL、PCL2 玩家互通。

技术选型（已调研确认）：

- **底层组网用 EasyTier 内核**（独立进程，进程外调用）：覆盖全部网络场景——IPv6 直连、IPv4 NAT 打洞、中继兜底，均由内核自动择优，Polymerium 无需感知。
- **互通用 Scaffolding 协议**（Polymerium 自己实现协议层）：该协议是独立开源规范（MIT），陶瓦（Terracotta）只是其参考实现之一；HMCL 与 PCL2 已通过各自实现接入同一生态。Polymerium 作为协议的新实现者直接进入生态，**不引入陶瓦**（避免双重封装与 AGPL 许可负担）。

## 期望效果

- 与实例生命周期一体化：选实例 → 开房间 → 生成房间码分享（链接/二维码）；对方输码 → 加入 → 进游戏。全程零网络知识门槛。
- 与 HMCL / PCL2 用户互通（Scaffolding 生态现成用户量）。
- P2P 直连优先（IPv6 / IPv4 打洞由内核择优），中继兜底；不做长期公开服务器托管定位。
- 联机功能本身零服务器成本起步（房间码发现与组网走 EasyTier 公共节点）。

## UI 构想（期望效果）

### 功能入口：两级，与实例绑定

- 联机两种角色都需要实例上下文（房主玩什么别人连什么；房客也要本地跑一个版本去连），入口不做成脱离实例的纯全局功能。
- **侧边栏常驻联机入口**：图标 + 文字 + 在房状态指示（有房间时明显可辨），点击进联机页；离开实例页后房间仍开着，用户随时能看见并管理它。
- **实例主页快捷入口**：实例的启动按钮旁提供联机开房入口，自动带上当前实例进入开房流程。

### 联机页：一个页面表达房间三种状态

- 联机状态固定为三种：未联机 / 开房中（房主）/ 已加入（房客），一个联机页内切换表达，不拆成多个页面。
- **未联机**：空态引导，提供开房间 / 加入房间两个动作。
- **开房中（房主视角）**：房间已开的醒目表达——房间码大字号展示（等宽字体，便于口头念给朋友），复制 / 分享链接 / 关闭房间三个动作；成员列表实时可见。
- **已加入（房客视角）**：房主与成员列表、延迟可见；离开房间动作。
- 房间状态是全局的一份真相（侧边栏指示与联机页共用），不随页面切换丢失。

### 关键交互

- **房间码是核心物件，要可念、可抄、可分享**：分享链接走 `poly://join/<房间码>` 形式——外部玩家点击链接唤起 Polymerium 自动解析进加入流程，与项目既有的内部 URI 规范衔接。
- 加入表单支持直接粘贴 `poly://` 链接自动解析；房间码输入即时校验格式，输错立刻反馈。
- **房客加入时也要选定实例**（加入后启动哪个版本连过去），默认最近使用的实例。
- 成员列表展示玩家名、房主标记与延迟（协议心跳自带延迟数据）。

## 调研注意事项

- **许可证**：EasyTier 为 LGPL-3.0——子进程调用 + 原样打包二进制，无链接义务；Scaffolding 协议仓库（`Scaffolding-MC/Scaffolding-MC`）为 MIT，可自由实现；陶瓦为 AGPL + 例外——仅作架构参考，不引入其代码或二进制。
- **房间码**：格式 `U/NNNN-NNNN-SSSS-SSSS`（N、S 为大写字母去 I/O + 数字），按 0-9、A-H、J-N、P-Z 映射 [0,33]、小端读整数能被 7 整除；对应 EasyTier 网络名 `scaffolding-mc-NNNN-NNNN`、密钥 `SSSS-SSSS`。
- **联机中心发现**：房主在 EasyTier 网络内以 `--hostname scaffolding-mc-server-{port}`（port 为 1024-65535 整数）暴露自己，房客据此找到联机中心；一个网络有且仅有一个联机中心。
- **协议面**：TCP、大端序帧；标准协议 `c:ping` / `c:protocols`（协商交集）/ `c:server_port` / `c:player_ping`（5s 心跳）/ `c:player_profiles_list`；命名空间机制允许各客户端自定义扩展协议，Polymerium 可用自有命名空间做差异化功能。
- **EasyTier 的 IPv6 行为**：是双栈并行打洞、择优连接，**并非显式 IPv6 优先**（无配置项，上游有 issue 在请求）；v2.3.0+ 支持无入站公网 IPv6 节点的打洞。对用户透明，无需 Polymerium 处理。
- **无官方 .NET 绑定**：EasyTier FFI 为 C ABI；业界成熟集成模式是"启动器管理内核子进程 + 本地接口交互"（HMCL 即如此），Polymerium 应采用进程外方案。
- **公共节点依赖**：陶瓦/HMCL 的信令与中继依赖 EasyTier 公共节点（如 `public.easytier.top`）；Polymerium 同样起步于此，后续再评估是否自建信令节点。
- **未定事项**（实施时再定，不在构想中写死）：侧边栏联机入口的具体位置（显眼单列 vs 低调置于底部）；房客加入时强制选实例还是默认最近实例；分享形态（链接/二维码）取舍；是否做跨房间的好友/历史记录；协议扩展命名空间的具体规划。
