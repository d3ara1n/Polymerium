# 事务化包更新

## 背景

当前已有批量更新包的界面和机制，但整合包开发中的更新往往会同时影响 profile、包版本、依赖关系、部署结果和配置文件。单纯完成包引用修改不足以让开发者安全评估一次更新，也不利于更新失败后的恢复。

## 做什么

重做批量更新的 UI 和机制，使一次包更新成为可审阅、可执行、可恢复的事务。更新前展示影响范围，更新过程中保持状态一致，更新失败时能够恢复到更新前的开发状态，并改善整个过程的操作体验。

## 期望效果

开发者在应用批量更新前能清楚知道会改变什么，可以选择接受或取消；更新会以一个完整操作提交，而不是留下部分修改。更新后能够继续部署和运行，出现问题时可以回到更新前的状态。

## 注意事项

包的依赖和其他元数据质量并不可靠，不能把上游依赖信息当作自动决策依据，也不能据此承诺完整的兼容性判断。更新影响展示应以实际 profile、版本选择、部署结果和用户可审阅的信息为主，依赖关系只能作为辅助参考。事务边界需要覆盖现有快照和实例状态机制，但具体实现方式留待实施时决定。
