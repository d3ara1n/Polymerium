# 账号数据损坏时软件内提示而不崩溃

## 背景

2026-10 Sentry 上报 POLYMERIUM-2R / POLYMERIUM-2S（同一用户，release 1.11.7）：持久化库中的账号行反序列化抛 JsonException，启动加载实例、实例页切换账号时直接崩溃。取证结论：坏行的 JSON 形状不可能由任何版本的应用内写入路径产生，属于用户在应用外手工修改数据库；两个 issue 已设为 Ignored。

这次暴露的缺陷与用户是否乱改无关：个别账号行损坏会让整个账号子系统不可用——启动、切换账号、打开账号管理页都在遍历全部账号时不容错，且账号页打不开意味着没有软件内自救途径，用户只能再次手改数据库。断电、磁盘损坏等造成的库里坏数据会落到同样的处境。

## 做什么

账号行反序列化失败时跳过损坏条目继续工作，在软件内提示用户存在被忽略的损坏账号，并提供从软件内删除损坏条目的途径。

## 想要什么效果

- 单个损坏的账号行只影响该行本身，其余账号及依赖账号的功能照常可用。
- 用户能感知到有账号条目因损坏被忽略，并能清除它。

## 调研所得的注意事项

- 账号的持久化写入只有两处：创建账号（类型标记与 JSON 同源）、启动时刷新令牌后的回写（只更新 JSON、类型不变）。正常写入的 JSON 必然包含全部 required 属性键，缺键只能来自外部修改——损坏无法靠写侧预防，只能靠读侧容错。
- 消费侧遍历账号的位置分散（账号页、实例首页、实例文件页、启动流程等），除批量遍历外还有按 UUID 读取单条的路径（如启动实例时选中账号），后者失败时同样需要不崩溃的用户可见反馈。
