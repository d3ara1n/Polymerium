# Git 工作流边界

## 背景

Polymerium 已经能够展示和执行一部分 Git 操作，但 Git 的命令行客户端与 LibGit2Sharp 并不共享同一套用户配置。凭据、签名、代理、钩子和其他 Git 行为可能由外部 Git 环境负责，应用内实现不能假定自己等同于用户安装的 Git。

## 做什么

明确并改善 Workspace 与外部 Git 操作之间的协作边界，使用户可以理解哪些操作适合在 Polymerium 中完成，哪些操作应交给外部 Git，并在两者之间安全地同步状态。重点覆盖项目初始化、状态刷新、外部变更发现、提交前后的内容一致性和误操作保护。

## 期望效果

用户能够在不丢失整合包开发成果的前提下，将 Polymerium 的 Workspace 与自己已有的 Git 配置和工作习惯结合起来。应用内 Git 功能不会伪装成完整 Git 客户端，也不会因 LibGit2Sharp 与外部 Git 配置不同而产生难以解释的行为。

## 注意事项

不能把 LibGit2Sharp 的行为当作系统 Git 的行为，也不能要求用户为两套实现维护互不相同的配置。涉及远端认证、签名、推送和其他外部 Git 能力时，需要保留外部 Git 的职责边界；具体交互方式实施时再结合现有能力和常见桌面 Git 工具的做法确定。
